# Session Capture: 2026-10-24 — Buttons, footer, save state and icon

## Decisions

### Button shape and size (shared `Button`, all screens)
**Chose:** radius `rounded-md` (4px, token `md`); default size `h-auto px-5 py-3.5 text-xs` (about 44px high); ghost buttons keep `px-3` through a compound variant
**Over:** `rounded-full` (tried first: "100% round", then "too round"), `rounded-xl` (also tried), `h-10 px-4 text-sm` (the old default), `px-3` for all buttons
**Because:** The user asked for all buttons, with taller and smaller buttons, then "less round", "even more square" and "more padding left and right, but not the ghost buttons". Scope "all buttons" was chosen in the questionnaire, so the change is in `src/ui/button.tsx` and affects every screen, the shell and the export.

### Card footer alignment (shared `CardFooter`, all screens)
**Chose:** `justify-end` in `CardFooter`; the confirmation card keeps its own `justify-center`
**Over:** right-aligning only the Profile footer
**Because:** The user asked for "all card footers" in the questionnaire. `ReadingReviewCard` now has its buttons on the right too.

### Profile: order of the footer buttons
**Chose:** Sign out on the left, Save on the right (DOM order changed, so the tab order follows)
**Over:** swapping only visually with `flex-row-reverse`
**Because:** The user wanted the two positions swapped. There is no "Cancel" on this screen, so the swap is between Save and Sign out (confirmed in the questionnaire).

### Profile: saved state only inside the Save button
**Chose:** the Save button shows a check icon and "Saved" when `saved` is true; `aria-live="polite"` on the button announces the change
**Over:** a separate "Saved" status element next to the button, or a green status
**Because:** The user did not want two elements for the saved state. The old `<span role="status">` with the emerald text is removed, so the saved state has no green success color any more.

### Profile: Save button inspector edits
**Chose:** `rounded-full border-0 border-neutral-100 leading-4 text-white dark:border-[oklch(27.07%_0.00918_285.77)] dark:text-[oklch(28%_0.01016_260.7)]` on this one Save button
**Over:** applying the edits in the shared `Button`
**Because:** Inspector edits are the user's explicit choice and were applied as listed, with the narrowest scope. The edits use design tokens `popover` (text) and `accent` (border), written as arbitrary `oklch` values.

### ReadingForm: card text color
**Chose:** `text-orange-700` on the ReadingForm card, light mode only (`dark:text-stone-50` stays)
**Over:** changing the shared `Card` in `src/ui/card.tsx`
**Because:** Inspector edit `text-stone-900` → `text-orange-700`, applied as listed with the narrowest scope. Parts with their own color class (description, teal header, info line) keep it.

### ReadingConfirmation: bigger check icon
**Chose:** `size-16` (64px) on the `CircleCheck` icon
**Over:** `size-12` (48px, the old size), `size-20` (80px, tried first)
**Because:** The user asked for a bigger icon, picked `size-20` in the questionnaire, then asked for "a bit smaller". Only this icon changed.

## Gotchas
- **Conflict, shown not resolved:** the user asked for "noch eckiger" (`rounded-md`) on all buttons, and later applied `rounded-full` to the Save button through the inspector. Save is round, all other buttons are square. Not decided whether Save should follow the shared radius.
- **DESIGN.md rule:** raw and arbitrary values must not be used when a token exists. The `oklch` values in the Save button are arbitrary values for existing tokens, applied because the user chose them in the inspector.
- **Not applied:** a request for `bg-slate-400` on the Profile card was never answered in the questionnaire (dismissed), so nothing changed there.
